# DR benchmark numbers (preliminary)

Source: `scripts/bench_dr.py --rounds 5` on the lab (VM 1, CirrOS), 2026-11-17, one run.
Method: each round writes 8 MiB of random data in the guest, then waits for one new replica
(interval 60 s, retention 6). Only the replicas created by this run are counted.

Result (n=5, all incremental; the run did not create a full copy):

- size, median 9179136 bytes, worst 9310208 bytes
- duration, median 553 ms, worst 564 ms

One run only; no statistical weight. Full-copy sync time, RPO and failover time are not measured yet.

## Site-loss failover (acceptance_m5.py, 2026-11-17, one run)

Source: `minihci vms failovers 1` (failover task 114), the API's stored values.
Method: primary hosts host1-3 destroyed, VM 1 failed over to the laptop (DR site).

- failover time (`failover_ms`): 2662 ms
- data loss bound (`data_loss_s`): 60.4 s, a lower bound from the last heartbeat; within the 90 s target (interval 60 s + 30 s slack)

The script's own guest marker check did not run: its console connection to the laptop timed out after the failover. Not measured: the marker-based data-loss value.
